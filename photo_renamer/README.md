# 부품 사진 파일명 자동화

현장에서 촬영한 부품 사진의 파일명을 **AI 판독 → 검수 → 일괄 적용** 3단계로 자동 변경하는 도구입니다.

## 파일명 규칙 (실제 운영 규칙 반영)

```
{연번 3자리}_{품번}_({브랜드}).JPG

예) 001_15KA-72040_(HYUNDAI CONSTRUCTION EQUIPMENT).JPG
    003_31LM-10310_(HYUNDAI).JPG
    004_31LM-10310_(HYUNDAI).JPG   ← 같은 부품 2번째 사진: 품번·브랜드 유지, 연번만 증가
```

- 연번은 전체 사진에 대해 1씩 증가 (시작 연번 조정 가능 — 기존 파일에 이어붙일 때)
- **새 부품의 첫 사진에서 품번·브랜드를 판독**하고, 다음 새 부품이 나올 때까지 이어받음
- 라벨이 안 보이는 측면/후면 사진은 자동으로 앞 부품에 묶임

## 사용법

1. **인식 엔진 선택**
   - `기본 OCR` (무료): 브라우저 안에서 처리 — **사진이 외부로 전송되지 않음**
   - `Claude` / `ChatGPT` / `Solar(Upstage)`: 각 서비스의 API 키 입력 시 사용. 정확도가 높음 (사진이 해당 API로 전송됨)
   - API 키는 기본적으로 **세션 저장**(sessionStorage — 브라우저 종료 시 삭제)이며, [이 브라우저에 저장]을 체크한 경우에만 localStorage에 보관됩니다. [키 삭제] 버튼으로 언제든 제거할 수 있습니다 (아래 "API 키 보안 주의" 참고)
2. **사진 불러오기**
   - `폴더 선택` (크롬/엣지): 완료 시 폴더 안 실제 파일명이 바로 변경됨
   - `사진 선택`: 새 이름의 사본을 ZIP으로 다운로드, 또는 `.bat` 스크립트로 원본 PC에서 일괄 변경
   - 순서는 파일명 자연 정렬(IMG_2 < IMG_10) = 촬영 순서
3. **인식 시작 → 검수**
   - 그룹(부품)별로 품번·브랜드 확인, 수정하면 그룹 전체에 반영
   - 인식 신뢰도 낮음 / 품번·브랜드 미확인 그룹은 붉게 표시
   - 그룹 경계가 틀리면: 사진 옆 **[✂ 여기부터 새 부품]** / 그룹 상단 **[↰ 이전 부품에 합치기]**
4. **적용** — 폴더 모드는 즉시 변경, 파일 모드는 ZIP 다운로드. 매핑 CSV·`.bat` 스크립트도 제공

> 처음이라면 `sample_photos/` 폴더의 연습용 사진 7장으로 흐름을 체험해 보세요. (`python3 make_samples.py`로 재생성 가능)

## 기존 자동화 시도의 오류를 이렇게 해결했습니다

| 기존 문제 | 해결 방법 |
|---|---|
| 텍스트/숫자 오독 | ① 품번 패턴 필터(현대 계열 `15KA-72040` 형식 점수화) ② O↔0, I↔1, S↔5, B↔8 등 **OCR 혼동 문자 정규화** ③ AI 비전 엔진 옵션(Claude/GPT) ④ 최종적으로 **검수 화면에서 사람이 확정** |
| 브랜드 오독 | 브랜드 사전 대조(복합어 우선) + 편집거리 1 퍼지 매칭. 사전은 화면에서 직접 추가/편집 |
| 같은 부품인데 앞 품번을 못 이어받음 | 품번이 안 보이는 사진은 자동으로 직전 부품에 묶음. 혼동 문자 정규화로 `72O40`≠`72040` 같은 오탐 분리 방지. 잘못 묶이면 검수에서 클릭 한 번으로 분리/병합 |

## 인식 엔진별 특징

| 엔진 | 비용 | 사진 전송 | 정확도 | 비고 |
|---|---|---|---|---|
| 기본 OCR (Tesseract) | 무료 | 없음 (로컬) | 인쇄 품질에 좌우 | 라이브러리·언어데이터 모두 동봉 — 오프라인 동작 |
| Claude (Anthropic) | API 사용량 | Anthropic API | 최고 | 모델 선택: Opus 5(기본)/Sonnet 5/Haiku 4.5 |
| ChatGPT (OpenAI) | API 사용량 | OpenAI API | 높음 | GPT-4o(기본)/4o-mini |
| Solar (Upstage) | API 사용량 | Upstage API | 높음(인쇄체) | Document OCR 텍스트 추출 후 규칙 매칭 |

## API 키 보안 주의

- AI 비전/고정밀 OCR 엔진은 **브라우저에서 각 제공사 API를 직접 호출**합니다
  (Anthropic 호출에는 `anthropic-dangerous-direct-browser-access` 헤더를 사용). 서버를 거치지 않으므로:
  - 키가 브라우저에 **평문으로 저장**되고, 네트워크 요청에 그대로 실립니다 → **개인 발급 키만, 신뢰된 PC에서만** 사용하세요
  - 기본 저장은 sessionStorage(브라우저 종료 시 삭제), [이 브라우저에 저장] 체크 시 localStorage(영구). [키 삭제]로 즉시 제거 가능
- **팀 공용 배포·실서비스에는 이 방식을 쓰면 안 됩니다.** 키를 서버(프록시)에 두고
  브라우저 → 자체 서버 → 제공사 API 로 중계하는 구조로 바꿔야 합니다.
  교체 지점은 `js/ocr.js`의 어댑터 함수 — fetch URL을 자체 프록시 엔드포인트로 바꾸고 키 헤더를 서버에서 붙이면 됩니다.

## 실행/배포

- 배포 페이지에서 바로 사용하거나, 저장소를 받아 `python3 -m http.server`로 열기
  (기본 OCR은 웹워커를 사용하므로 파일 더블클릭(file://)이 아닌 **http 접속**이 필요합니다. 배포 페이지 사용 권장)
- 폴더 모드(실제 파일명 변경)는 크롬/엣지에서 동작

## 구조 (이어서 개발하실 분)

```
index.html          화면
js/logic.js         핵심 규칙 (품번 추출·혼동 보정·그룹핑·파일명 생성) — node로 테스트 가능
js/ocr.js           인식 엔진 어댑터 4종 (Tesseract/Claude/OpenAI/Upstage) — 새 엔진 추가 지점
js/app.js           UI 흐름
lib/                Tesseract·JSZip 로컬 번들 (+ core wasm, eng 언어데이터)
test/logic.test.js  규칙 단위 테스트: node test/logic.test.js
make_samples.py     연습용 샘플 사진 생성
```

- 품번 패턴 추가: `js/logic.js`의 `PART_RE`·`scorePart`
- 브랜드 기본 사전: `js/logic.js`의 `DEFAULT_BRANDS`
- 새 AI 엔진 추가: `js/ocr.js`에 어댑터 함수 추가 → `js/app.js`의 엔진 select와 `MODEL_OPTIONS`에 등록
